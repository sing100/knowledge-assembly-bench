# 把书拆成知识包（book-to-pack）

产出一个 JSON 文件，可在知识组装台页面里用「导入知识包」直接加载。学习者会：把每张卡连到上级卡、给每条连线配关系词、给每张卡配含义，并把书连到作者和书中概念。拆得好不好，就看这四件事是否都有唯一、可推理的正确答案。

## 第一步：定类型

- **概念包**：根是一个思想体系（如「斯多葛主义」）。书只是其中一枝，书里的概念通过关联线（refs）挂到书上。一个学派里每本书输出的概念不多时，用这种。
- **书本包**：根是一本书。概念密度高、结构复杂的书单独成包。

## 第二步：拆树（parts + parent）

**概念包**的推荐一级分支：人物 / 著作 / 学说的几大分支（如物理学、伦理学、逻辑学）/ 实践方法。

**书本包**的推荐一级分支，按「这本书在回答什么问题」往下拆：
1. 背景：作者、写作处境、写给谁
2. 核心问题：这本书要解决什么
3. 主张：3～6 条核心观点
4. 方法 / 练习：怎么做
5. 金句：挂在它所支撑的主张或练习下面，不单独成枝
6. 传承：上承谁、影响谁

拆的规则：
- 每张卡只有一个上级（parent），根节点的 parent 为 null。
- 每一级都能用一句话回答「它为什么挂在这里」，那句话就是关系词。
- 卡片总数 20～40 张，深度不超过 4 层；单个节点的子节点不超过 6 个。
- 同一层的兄弟卡片要能互相区分，不要放两张学习者无法判断归属的卡。
- 卡片标签要短：概念 2～8 字；书名用《》；引语用「」，不超过 20 字。

## 第三步：写关系词（links）

- 每条树边一个 `label`，2～6 字，读作「上级 —label→ 下级」，如「伦理学 —终极目标→ 依顺自然而活」。
- 兄弟之间的关系词尽量不同，否则学习者无法判断哪个词放哪条线；确实同类时（如「四主德」）可以重复。
- links 数量 = parts 数量 − 1。

## 第四步：写含义（note）

- 每张卡一个 `note`，4～10 字，是对这张卡的最短解释（如「可控 vs 不可控」）。
- 含义之间不能互相替换；避免出现两张卡的 note 都适用于同一张卡。
- 不要在 note 里重复 label 本身。

## 第五步：关联线（refs，可选）

- 方向永远是 **书 → 作者** 或 **书 → 概念**：学习者先认识书，再看它是谁写的、提出了哪些概念。不要写成 概念 → 出处。
- `type`: `author`（书 → 人）或 `source`（书 → 概念）。
- `label`: 2～6 字，如「作者」「讲授者」「开篇提出」「书中阐述」。
- 只写有据可查的关系；一个概念可以来自多本书。
- refs 的两端都必须是已存在的卡片，且不能和树边重复。

## 第六步：核对事实

人物、书名、引语出处要可查证。引语标注卷章（写在 note 里，如「卷八·47」）。拿不准的不要写。

## 输出格式

```json
{
  "id": "stoicism",
  "title": "斯多葛主义",
  "subtitle": "古希腊罗马哲学",
  "intro": "一句话介绍这个包。",
  "kind": "concept",
  "parts": [
    { "id": "core", "label": "斯多葛主义", "parent": null, "note": "古希腊罗马哲学" },
    { "id": "people", "label": "人物", "parent": "core", "note": "学派里的人" }
  ],
  "links": [
    { "a": "core", "b": "people", "label": "代表人物" }
  ],
  "refs": [
    { "a": "meditations", "b": "marcus", "type": "author", "label": "作者" }
  ]
}
```

- `id` 用小写英文和连字符；同一个概念在不同包里尽量用同一个 id，方便以后互相连接。
- `kind`: `concept` 或 `book`。
- 写完运行校验：`node skills/book-to-pack/scripts/validate.js 你的包.json`，没有报错再交付。

完整示例见仓库里的 `packs/stoicism.json`。
