# 把书拆成知识包（book-to-pack）

产出一个 JSON 文件，可在知识组装台页面里用「导入知识包」直接加载。学习者会：把每张卡连到上级卡、给每条连线配关系词、给每张卡配含义，并把书连到作者和书中概念。拆得好不好，就看这四件事是否都有唯一、可推理的正确答案。

## 适用范围

只做学习知识类书籍：哲学、社科、学科入门、历史、方法与技能。小说和以情节为主的书不做——它们的骨架是人物关系网，不是树，硬拆会误导学习者。

## 第零步：先判定骨架（shape）

拆之前先回答：这本书的骨架是哪一种？

| shape | 骨架 | 典型书 | 树怎么长 |
|---|---|---|---|
| `tree` | 分类：整体由几大部分组成 | 哲学体系、学科入门、概念百科 | 上级 = 类别，下级 = 成员 |
| `argument` | 论证：一个总论点，由分论点支撑，分论点由证据/实验支撑 | 《思考，快与慢》《枪炮、病菌与钢铁》 | 根 = 总论点，二级 = 分论点，三级 = 概念，叶 = 证据/实验/例子 |
| `sequence` | 顺序：步骤、阶段或时间先后 | 《原子习惯》、历史书、方法书 | 有先后的兄弟卡写 `order`（1..n），学习者要连对上级也要排对顺序 |

一本书三种都不像（主干是人物关系或情节），就说明不适合做成包，直接告诉用户，不要硬拆。

教科书类的前后依赖（学 A 才能懂 B）不改变 shape，用 `depends` 关联线表达。

## 第一步：定类型

- **概念包**：根是一个思想体系（如「斯多葛主义」）。书只是其中一枝，书里的概念通过关联线（refs）挂到书上。一个学派里每本书输出的概念不多时，用这种。
- **书本包**：根是一本书。概念密度高、结构复杂的书单独成包。

## 第二步：拆树（parts + parent）

**概念包**的推荐一级分支：人物 / 著作 / 学说的几大分支（如物理学、伦理学、逻辑学）/ 实践方法。

**书本包**的推荐一级分支，按「这本书在回答什么问题」往下拆：
1. 背景：作者、写作处境、写给谁
2. 核心问题：这本书要解决什么
3. 主张：3～6 条核心观点
4. 方法 / 练习：怎么做
5. 金句：挂在它所支撑的主张或练习下面，不单独成枝
6. 传承：上承谁、影响谁

拆的规则：
- 每张卡只有一个上级（parent），根节点的 parent 为 null。
- 每一级都能用一句话回答「它为什么挂在这里」，那句话就是关系词。
- 卡片总数 20～40 张，深度不超过 4 层；单个节点的子节点 2～7 个。
- 单子节点规则：一个节点只有 1 个子节点时，必须能说明它为什么是链而不是类：顺序链（印象 → 认可）、论证链（逻各斯 → 世界主义）、方法配唯一经典例子（代表性启发 → 琳达问题）可以留；如果它是一个分类却只有一个成员，学习者根本没有选择可做，要么把父子合并，要么补一个真实的兄弟节点，不要留一条“走过场”的边。
- 书太大装不下，就拆成几个包，同一概念在不同包里用同一个 id。
- 同一层的兄弟卡片要能互相区分，不要放两张学习者无法判断归属的卡。
- 卡片标签要短：概念 2～8 字；书名用《》；引语用「」，不超过 20 字。

## 第三步：写关系词（links）

- 每条树边一个 `label`，2～6 字，读作「上级 —label→ 下级」，如「伦理学 —终极目标→ 依顺自然而活」。
- 同一上级下的关系词必须不同，否则学习者无法判断哪个词放哪条线。不要用「三大分支」「四主德」这类笼统词当关系词：它们说的是数量，不是内容，学习者光看词分不清哪条是哪条。改成内容词，如三大分支 → 宇宙本性 / 如何生活 / 如何思考，四主德 → 判断善恶 / 面对恐惧 / 公正待人 / 欲望有度。只有当兄弟卡本身就是同类并列、且卡片标签已经能区分时，才允许重复，且要在交付检查里写明理由。
- links 数量 = parts 数量 − 1。

## 第四步：写含义（note）

- 每张卡一个 `note`，4～10 字，是对这张卡的最短解释（如「可控 vs 不可控」）。
- 含义之间不能互相替换；避免出现两张卡的 note 都适用于同一张卡。
- 不要在 note 里重复 label 本身。

## 第四步半：写解释（explain）

学习者多半没读过这本书。点开一张卡，右侧会立刻显示 `explain`，他们先读懂这张卡是什么，再去推理它挂在哪。

- 1～3 句大白话，40～120 字，绝不要短于 20 字；只写一句标签式的话（如“提出这些理论的心理学家。”）等于没解释，必须带一个具体例子或场景。
- 根卡的 intro 和 explain 必须一致：intro 是一句话模型（如“幸福只取决于品格和判断，不取决于外在遭遇。”），不是“组装某某。”；如果根下除了学说分支还有人物、著作、修习等分支，根 explain 不能只说“整个体系分三块”，要说清哪三块是学说分支、其余是什么，否则学习者会按“三块”去数，结果数出六个。
- 只解释这张卡**本身**，不要直接说出它的上级、关系词或 note，否则就成了送答案。可以留线索，比如「整个体系分三块」。
- 根卡的 explain 要概括全书或全体系的核心观点，一级分支的 explain 说清这一大块讲什么。
- 事实要可查：年份、人物、实验结论都别编。

## 第五步：关联线（refs，可选）

关联线是树以外的横向关系。默认隐藏，学习者选中一张卡时才显示，所以宁少勿滥：一个包 5～15 条，只写学习者真正需要知道的。

| type | 方向 | 含义 | label 示例 |
|---|---|---|---|
| `author` | 书 → 人 | 谁写的 | 作者、讲授者 |
| `source` | 书/人 → 概念 | 谁提出的、出自哪里 | 书中阐述、首次提出 |
| `depends` | 后学的 → 先学的 | 不懂 B 就看不懂 A | 以…为前提、建立在 |
| `causes` | 原因 → 结果 | 因果、导致 | 导致、解释了 |
| `contrasts` | 任一方向 | 对立、易混淆 | 相对于、别混淆 |
| `example` | 概念 → 例子 | 这个实验/案例说明那个概念 | 例证、典型实验 |

- 方向要能读成一句话：「a —label→ b」。
- `label`: 2～6 字。
- 只写有据可查的关系；一个概念可以来自多本书。
- refs 的两端都必须是已存在的卡片，且不能和树边重复。

## 第六步：核对事实

人物、书名、引语出处要可查证。引语标注卷章（写在 note 里，如「卷八·47」）。拿不准的不要写。

## 第七步：交付前自查（缺一不可）

写完先跑这三条，全部通过再交付，不要只凭感觉说“差不多了”：
1. `node skills/book-to-pack/scripts/validate.js 你的包.json` —— 没有错误，警告要逐条处理或写明理由。
2. `node tests/state.test.js` —— 无浏览器测试：树、关系词、关联线、词块答案、内嵌包一致性，全部通过；单子节点只报警告，但要在交付里说明它是链还是类。
3. `node scripts/sync-packs.js` —— `packs/*.json` 是唯一数据源，`index.html` 里内嵌的包是生成的副本，不要手改内嵌包；改完包必须同步，否则线上站不会变。
自查清单：关系词同一上级下无重复；note 之间不能互相替换；深度 ≤4、子节点 ≤7、卡数 20～40；每张卡 explain 20～140 字（理想 40～120）；intro 是一句话模型且与根 explain 一致；refs 两端存在且不是树边；sequence 包兄弟 order 齐全且为 1..n。

## 输出格式

```json
{
  "id": "stoicism",
  "title": "斯多葛主义",
  "subtitle": "古希腊罗马哲学",
  "intro": "一句话介绍这个包。",
  "kind": "concept",
  "shape": "tree",
  "parts": [
    { "id": "core", "label": "斯多葛主义", "parent": null, "note": "古希腊罗马哲学", "explain": "公元前3世纪起于雅典的哲学学派……" },
    { "id": "people", "label": "人物", "parent": "core", "note": "学派里的人", "explain": "把这套哲学提出、整理、实践出来的那些人……" }
  ],
  "links": [
    { "a": "core", "b": "people", "label": "代表人物" }
  ],
  "refs": [
    { "a": "meditations", "b": "marcus", "type": "author", "label": "作者" }
  ]
}
```

- `id` 用小写英文和连字符；同一个概念在不同包里尽量用同一个 id，方便以后互相连接。
- `kind`: `concept` 或 `book`。
- `explain`: 每张卡都要写，见「第四步半」。
- `shape`: `tree` / `argument` / `sequence`，不写按 `tree`。
- `sequence` 包里，有先后的兄弟卡加 `"order": 1` 这样的字段；同一组兄弟要么全写、要么全不写。
- 写完运行校验：见第七步，validate.js + tests/state.test.js + sync-packs.js 三条全部通过再交付。

示例：
- `packs/stoicism.json`：tree，概念包
- `packs/thinking-fast-and-slow.json`：argument，书本包
- `packs/atomic-habits.json`：sequence，书本包
